# Windows Tauri port status

The `rewrite/tauri-windows` branch builds a Windows Tauri 2 application from the existing React renderer. The Electron main process, preload bridge, and Electron packaging hooks are removed. Its package manifest has no Electron runtime or packager dependencies; Node is build tooling. Rollback uses a separately retained Electron installer, and the original source remains on baseline commit `00380c798ea3a8447270e8bbd367e921d03d154b`. Source manifests remain at `2.0.0`. The current local installers were built from commit `0c1a8341` with temporary version `2.0.0-0c1a8341`; the build restored the package, Cargo, Tauri, and lockfile versions afterward.

## Build

Use Node 24 from `.nvmrc`, pnpm 10.34.4, Rust MSVC for `x86_64-pc-windows-msvc`, Microsoft C++ Build Tools, and WebView2. From the repository root:

```powershell
pnpm run build:tauri:win
pnpm run build:tauri:win:replacement
```

Each command parses both bundled PowerShell hooks without executing them, builds the locked Rust helpers, type-checks the Tauri renderer contracts, builds all six HTML entry pages, compiles the Tauri host, creates an NSIS installer, and writes SHA-256 metadata under `release/tauri/<profile>`. The rewrite-branch Windows workflow provisions Rust, builds both profiles, and uploads installers as artifacts; it runs no tests. Legacy test, lint, and release jobs skip the rewrite branch.

## Recorded runtime errors

The `2.0.0-0c1a8341` follow-up build retains each song's encoded protobuf payload and decodes only the requested song. Initialization still decodes every record once to build its indexes and reject malformed data; it no longer keeps expanded song and difficulty structs. Map rows use CSS stacking isolation instead of forced identity 3D transforms and hidden backfaces. The six local windows request WebView2's low memory target while minimized, then restore the normal target when shown. This uses [Microsoft's memory-target API](https://learn.microsoft.com/en-us/dotnet/api/microsoft.web.webview2.core.corewebview2.memoryusagetargetlevel), which is best effort and keeps scripts and network connections running. ## Implemented in the Rust host

- Separate preview and replacement identifiers and settings directories. Preview blocks shared library/content mutations while legacy `BSManager.exe` runs, except Steam downloads: those download into a private staging folder and move into a distinct version folder when complete. Operations serialize within the app and across Preview/Replacement processes with a Windows mutex keyed by normalized library root. Relocation locks both source and destination roots. Tauri installer configuration does not claim protocols or file extensions. On first app start, replacement registers `bsmanager`; preview registers the separate `bsmanager-preview` launch scheme so its shortcuts cannot redirect existing BSManager links. Replacement migration restores recorded legacy handlers when the old uninstaller removed them or they still point to the removed executable; migration skips unrelated current commands, though normal startup still claims `bsmanager`. Visible settings manage maps, playlists, and model links. Playlist settings also manage `.bplist`; handlers are backed up per user and restored on uninstall only while still owned by that profile. When profiles claim a shared association in sequence, uninstall falls back through a removed sibling profile's backup instead of restoring a stale executable path. The replacement preinstall hook backs up legacy config and protocol/file-association registry keys, invokes the registered Electron uninstaller, and restores the backed-up config if that uninstaller removed it. It aborts on ambiguity, a running legacy process, or uninstall failure; it does not delete game libraries. Preview import marker v6 fills missing legacy static settings and renderer preferences, launch options, download choice, audio level, and dismissal choices while preserving values already present in Preview. Replacement marker v1 imports only allow-listed legacy renderer preferences missing from Tauri localStorage, while leaving the legacy files untouched. Last-launched version matching treats omitted store flags as false. Version colors remain in the library's `config.cfg`, which the installed-version scan reads. Encrypted legacy Meta tokens are excluded and require Meta login again.
- Main window setup and startup routing, native dialogs, window controls, drag/drop events, single-instance handling, protocol registration and routing, bundled plus upstream-refreshed version catalog, installation-folder operations, local version discovery/edit/clone/uninstall, shared-folder links, launch-shortcut creation, LIV registry shortcuts with saved launch options, and restart-after-reply. Installed-version scans read `config.cfg` colors and `metadata.config`; they stay read-only while legacy BSManager is open and use stable path-derived IDs for versions without metadata. Main window state restoration is disabled so each new main window opens at its configured 1080×720 size. Library relocation and version cloning use cancellation-aware staged copies; failed copies preserve the source and prior destination.
- Steam sidecar download routes replace an active in-process download before waiting on the library lock; sidecar exits on broken output pipes instead of leaving a child behind. Isolated Steam downloads preserve pending files in private staging so retries can resume after legacy BSManager closes. Meta login/session routes and Meta downloads are also ported. Meta manifest paths reject invalid or colliding Windows names; each file is staged, size/hash verified, and swapped into place so cancellation or failure preserves the previous file. Game launch, Windows VR runtime and sideload controls, and supporter data are also ported. Elevated launch preserves the `-vrmode None` argument and carries Steam, FPFC, and parsed custom environment values through a temporary record consumed and removed by the admin helper. Close-on-launch tracks a newly created Beat Saber process by PID, creation time, and executable path.
- ModelSaber search and lookup; model download, one-click installation, local listing, export, and deletion. Local model scans and archive source scans do not create missing model folders. Downloads reject symlink/file-folder targets and stage replacements so failed transfers preserve existing models; one-click copies use cancellable staging.
- BeatSaver map and playlist search/details; local map listing, deletion, import/export, download, and one-click install. Map installs stage archive extraction, compute the Beat Saber hash, validate it against BeatSaver, then move the map into the managed folder. Copies into other installed versions reject symbolic-link destinations and use cancellable staging before replacement. Map listing avoids creating song metadata or folders while legacy BSManager is open; normal scans preserve the existing added-date metadata behavior under the library lock. Rust converts local cover and song paths with `WebviewWindow::convert_file_src` before sending maps to the renderer; each loaded `CustomLevels` root and canonical linked root is added to the asset scope. Packaged display remains unverified. Map, playlist, and model archive exports check cancellation during large file copies; ZIP mod import checks during extraction.
- BeatSaver response caching for maps fetched during the current session. The scraped song-detail cache loads the existing replacement-profile protobuf file, refreshes it from the current sources with ETag support, stores it beside profile settings, and supplies detail data to local maps and playlists. The per-folder `map-info-cache.json` is loaded, reused, and debounced to disk in the same location; deleted map entries are removed. Preview caches remain separate.
- Playlist listing, file import, install, delete, archive export, download, and one-click install. Download progress keeps the renderer’s existing payload shape.
- BeatMods availability and health routes; installed-mod discovery, including library files matched to manifests, DLL/ZIP import, download and content-hash validation, installation, removal, and remove-all. Archive member paths reject traversal and symbolic links. ZIP downloads stream to temporary files; verification hashes entries while streaming, and ZIP extraction plus raw DLL copies honor chunked cancellation. Mod file swaps preserve prior files on failure, and BSIPA replacement stages existing IPA contents. BeatMods requests retry transient connection/server failures and honor cancellation; download and IPA cancellation still need runtime review.
- Tauri updater checks use profile-specific endpoint/public-key build settings. Downloads stream progress to the requesting window, support request cancellation, verify signatures before installation, and install through the Tauri Windows updater. Updates stay disabled when signed profile settings are absent. Taskbar progress follows renderer progress on the originating window.
- Tauri logs use info level and redact registered secret strings plus Oculus token patterns before writing to any target. Renderer `add-filter-string` and `add-filter-pattern` routes update the shared formatter filters.
- Static configuration commands preserve unrecognized fields during file round trips. The system-proxy setting disables OS proxy use by default and applies Windows proxy settings to newly created Rust HTTP clients when enabled, including after a settings change. Tauri Channels carry ordered request streams; `request`, `send_lazy`, and `cancel_request` reject non-application windows. `cancel_request` and window destruction cancel work belonging to that window, and cancellation from another app window is rejected.

## Replacement rollback

The replacement preinstall hook stores a timestamped backup under `%LOCALAPPDATA%\BSManager\migration-backups\`. `migration.json` lists the saved Electron `config.json`, protocol/file-association registry exports, and legacy-owned handlers to restore to the new executable on first startup. The baseline Electron builder config does not enable app-data deletion; [electron-builder documents this option as defaulting to false](https://www.electron.build/docs/nsis/#deleteappdataonuninstall), so the old Local Storage database remains available for Preview's explicit preference import after a standard uninstall. If Electron's uninstaller fails, the hook restores `config.json` when missing and restores only association command values that the uninstaller removed, leaving registrations that still exist untouched. Game libraries are not removed.

If Electron uninstall succeeds but the Tauri install then fails, reinstall the retained Electron installer first. If settings are missing or damaged, restore the saved `config.json` to `%APPDATA%\bs-manager\config.json`. After Electron returns to its original install path, import the relevant registry exports listed in `migration.json` to restore prior protocol and `.bplist` handlers. Import HKCU exports as the same Windows user; HKLM exports may require elevation. Review each export before importing if another app has since claimed that handler.

Keep the existing Electron installer for rollback. Current Tauri installers are local build artifacts only. Do not distribute or install the replacement profile until migration, installer recovery, runtime parity, and visual review are complete.
